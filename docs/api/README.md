# API documentation

The generated OpenAPI contract will live in `contracts/openapi/`. Public reads and authenticated admin operations must be documented by that contract. Do not maintain a competing handwritten type definition for API payloads.

## Admin domain operations

BE-16 protects versioned administrator operations with OIDC bearer tokens:

- `POST /api/v1/admin/domains` creates a canonical domain and its default crawl policy.
- `GET /api/v1/admin/domains` lists active domains in canonical-domain order using `cursor` and `limit` (default `50`, maximum `100`).
- `GET /api/v1/admin/domains/{canonical_domain}` returns one active domain.
- `POST /api/v1/admin/imports/csv` imports a bounded CSV document and returns aggregate row outcomes.
- `PATCH /api/v1/admin/domains/{canonical_domain}/policy` updates the enabled state, priority, and crawl interval.
- `GET /api/v1/admin/audit-events` returns a bounded page of immutable administrator audit events.

Every endpoint requires `Authorization: Bearer <OIDC_ACCESS_TOKEN>`. Tokens must be RS256-signed, issued by `ADMIN_OIDC_ISSUER`, addressed to `ADMIN_OIDC_AUDIENCE`, and verified against `ADMIN_OIDC_JWKS_URL`. Auth0 access tokens carry `admin:read` and `admin:operate` in the standard `permissions` claim; `admin:read` permits reads and `admin:operate` permits reads and mutations. The API caches the JWKS briefly, refreshes it when a key is unknown or stale, and bounds identity-provider requests with the dependency timeout.

## Operations and rule management

Operators can inspect recent crawl attempts and request a retry only when the server confirms that the attempt is terminal and safe to retry. Each attempt includes a retry state that distinguishes active work, automatic retries, blocked failures, and manually retryable failures. Safety, robots-denied, and cancelled work is never operator-retryable. Every accepted retry creates a new queued attempt and audit event; the failed attempt remains immutable.

`POST /api/v1/admin/country-enrichment/recrawl` requires `admin:operate` and schedules enabled,
previously successful domains that have no country observation. It only changes scheduler
eligibility, writes one audit event, and returns the number scheduled.

Detection rules are scoped to the existing technology catalogue. Operators save a validated JSON draft, run a deterministic signal fixture test, publish an immutable version after a passing test, then activate, deactivate, or roll back to one published version. A technology has at most one active version. Workers load active versions for each new crawl, while historic detections keep their original rule version and evidence.

`ADMIN_RATE_LIMIT_PER_MINUTE` defaults to `60` for reads and `ADMIN_MUTATION_RATE_LIMIT_PER_MINUTE` defaults to `30` for mutations; both must be positive. Rate limiting is per authenticated subject and operation class. Successful domain, import, and policy mutations write immutable audit events containing the actor, action, resource, timestamp, and safe operation metadata. The local development values in `.env.example` are placeholders, not deployment credentials.

Known errors use the stable `{"error":{"code":"...","message":"..."}}` shape. The OpenAPI contract is generated by `pnpm api:openapi`, and the TypeScript client is regenerated with `pnpm api:client:generate`.

## Operational health endpoints

BE-01 exposes operational-only endpoints outside the public product API contract:

- `GET /healthz` returns `200 {"status":"ok"}` when the API process is running.
- `GET /readyz` returns `200` only when PostgreSQL, Redis, and Meilisearch are reachable; it otherwise returns `503` and reports only each dependency's `ready` or `unavailable` state.

Neither endpoint returns configuration values, connection strings, credentials, or raw dependency failures.

`GET /metrics` is an internal Prometheus scrape endpoint rather than a product API route. It exposes only bounded operational labels and never includes domain names, request URLs, credentials, tokens, raw error strings, or evidence.

`DEPENDENCY_CHECK_TIMEOUT_MS` bounds each dependency readiness check and defaults to `2000`. It must be a non-zero positive integer.

## Public intelligence reads

BE-15 exposes unauthenticated, read-only endpoints below `/api/v1/public` for domain search,
domain profiles and history, technology library results, normalized comparison, and aggregate
analytics. All collection responses use a maximum `limit` of 100. Search accepts text plus
technology, category, country, crawl recency, confidence, and allowlisted sort filters; each
result page also includes current-match technology, category, and country facet counts, bounded
to 100 values per facet by the rebuildable Meilisearch projection. Profiles, comparison, and analytics read the
authoritative PostgreSQL projection. Public errors use the same stable error envelope as admin
operations.

The domain-profile endpoint returns the canonical identity, first-indexed and last successful crawl times,
country when known, current technology detections, detection method/rule version/confidence, and
redacted evidence. Separate domain endpoints return cursor-paginated technology changes and crawl
history plus sanitized crawl response headers, redirect chains, and country observations.

`POST /api/v1/public/domains/{canonical_domain}` records a public refresh request and returns
`202 Accepted`; it does not enqueue a job directly. The scheduler reserves the eligible crawl and
uses its normal outbox path. `PUBLIC_REFRESH_COOLDOWN_HOURS` defaults to `24` and applies one
accepted request per canonical domain; a request during the cooldown returns `429` with
`Retry-After`. A domain with crawling disabled returns `409` and is not scheduled.
